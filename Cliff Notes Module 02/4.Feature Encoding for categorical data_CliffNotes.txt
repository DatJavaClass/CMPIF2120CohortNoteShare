1. WHY ENCODE CATEGORICAL DATA
  - Most machine learning algorithms operate only on numerical
    values. Real data is full of strings. So the strings have to
    be mapped to numbers in some way.
  - The lecture's opening example: three levels, high, medium,
    and low, mapped to 2, 1, and 0.
  - There are many ways to do the mapping, and picking the wrong
    one quietly tells the model something about the data that is
    not true. That is the whole lesson.
  - KEY TERM: categorical data: attributes whose values are
    labels from a fixed set of categories rather than measured
    quantities. (added definition)
  - KEY TERM: feature encoding: the transformation from string
    categories to numbers that an algorithm can consume. (added
    definition)
  - Three techniques are covered, matched to three situations:
      Label encoding: order does not matter to you, you just
        need numbers.
      Ordinal encoding: the categories have an inherent order
        and you specify it.
      One-hot encoding: there is no order and the model must not
        be allowed to assume one.
  - Tools: pandas plus scikit-learn's preprocessing module
    (LabelEncoder, OrdinalEncoder, OneHotEncoder) and pandas
    get_dummies. The Titanic notebook imports all three.

2. THE TITANIC DATASET
  - The lecture's data is the Titanic dataset. It started as a
    Kaggle competition years ago and became a standard starter
    dataset for classification problems. The notebook loads it
    from seaborn.
  - Only five attributes are kept: survived, sex, embarked,
    class, who. Rows with any missing values are dropped so
    missing data is not a concern here.
  - The columns:
      survived: 0 did not make it, 1 survived.
      sex: male or female.
      embarked: port of embarkation, C for Cherbourg, Q for
        Queenstown, S for Southampton.
      class: First, Second, Third.
      who: man, woman, child.
  - KEY TERM: classification: predicting a category (here,
    survived or not) rather than a number. (added definition)

3. LABEL ENCODING
  - KEY TERM: label encoding: assign each distinct category an
    integer, 0 through k minus 1 for k categories. scikit-learn's
    LabelEncoder does this with fit_transform on the column
    (fit_transform learns the mapping and applies it in one
    call). (added definition)
  - The lecture's flow on Titanic: encode sex into a new column
    sex_le. To inspect the mapping, select just the two columns
    and drop_duplicates(), which leaves one row per unique
    (original, encoded) pair. Two rows come back: female became
    0, male became 1.
  - The order is alphabetical. LabelEncoder sorts the distinct
    values and numbers them in that order. That is fine when the
    order carries no meaning and nothing downstream treats the
    numbers as ranks.
  - For example, a shirt table with a color column holding red,
    blue, green, blue, red, green:

      import pandas as pd
      from sklearn.preprocessing import LabelEncoder
      df_sh = pd.DataFrame({"color": ["red", "blue", "green",
                                      "blue", "red", "green"]})
      le = LabelEncoder()
      df_sh["color_le"] = le.fit_transform(df_sh["color"])
      print(df_sh[["color", "color_le"]].drop_duplicates())

    Output:

         color  color_le
      0    red         2
      1   blue         0
      2  green         1

    blue is 0, green is 1, red is 2. Alphabetical, nothing to do
    with the order the values appeared in. le.classes_ holds
    ['blue', 'green', 'red'] if you need the mapping back.
  - KEY TERM: drop_duplicates(): pandas method that removes rows
    whose selected column values repeat, leaving each unique
    combination once. The lecture uses it to reveal a mapping.
    (added definition)

4. ORDINAL ENCODING
  - Pure alphabetical order sometimes will not cut it, because
    the data has an inherent order. Then you use ordinal
    encoding and specify the order yourself.
  - KEY TERM: ordinal encoding: integer codes assigned in an
    order you specify, so that a bigger number means a higher
    rank. (added definition)
  - The lecture's flow on Titanic: class has an order. Build an
    OrdinalEncoder with categories=[['Third', 'Second',
    'First']], fit_transform the class column into class_ordinal,
    then select the two columns and drop_duplicates(). Three rows
    come back: Third became 0, Second became 1, First became 2.
    Higher value for higher class of service. The order was
    chosen by us, and any order you specify works.
  - Two mechanics worth noting (added):
      OrdinalEncoder takes a 2-D input, so the column is passed
        as df[['class']] with double brackets, not df['class'].
        LabelEncoder takes the 1-D series.
      The categories argument is a list of lists, one inner list
        per column being encoded, in the order you want the codes
        to climb.
  - For example, shirt sizes S, M, L, XL, where alphabetical
    order (L, M, S, XL) would be nonsense:

      from sklearn.preprocessing import OrdinalEncoder
      df_sh["size"] = ["M", "S", "XL", "L", "S", "M"]
      oe = OrdinalEncoder(categories=[["S", "M", "L", "XL"]])
      df_sh["size_ord"] = oe.fit_transform(df_sh[["size"]])
      print(df_sh[["size", "size_ord"]].drop_duplicates())

    Output:

        size  size_ord
      0    M       1.0
      1    S       0.0
      2   XL       3.0
      3    L       2.0

    S is 0, M is 1, L is 2, XL is 3, exactly the list order. Note
    the codes come back as floats (1.0, not 1). That is how
    OrdinalEncoder returns them.

5. MANUAL ORDINAL ENCODING WITH A DICTIONARY
  - The lecture does the same job by hand, more lines, no
    encoder call. The dataset is a small education table: five
    rows, four distinct degrees, High School, Bachelors, Masters,
    PhD.
  - The mechanism: build a dictionary where the degree names are
    the keys and 0, 1, 2, 3 are the values. Then create a new
    column education_encoded by running the education column
    through map() with that dictionary. Every High School becomes
    0, every Bachelors 1 (rows 1 and 4 in the lecture's table),
    every Masters 2, every PhD 3.
  - KEY TERM: map(): pandas Series method that replaces each
    value with its lookup in a dictionary (or the result of a
    function). A value missing from the dictionary becomes NaN.
    (added definition)
  - For example, the shirt sizes again, by hand:

      size_map = {"S": 0, "M": 1, "L": 2, "XL": 3}
      df_sh["size_map"] = df_sh["size"].map(size_map)

    size_map matches size_ord in every row (M 1, S 0, XL 3, L 2,
    S 0, M 1), except that the dictionary route gives integers
    while OrdinalEncoder gave floats. Same information, and
    the dictionary version is easier to read six months later.

6. ONE-HOT ENCODING
  - The third case: there is no order and you should not use
    one. If you adopt an order by accident or on purpose, you
    risk assuming a wrong order in your modeling, and the results
    may not be what you expect.
  - Why that risk is real (added): a numeric code says to the
    model that Southampton (2) is "more" than Cherbourg (0), and
    that Queenstown (1) sits halfway between them. Linear models
    and distance-based models will take that literally.
  - KEY TERM: one-hot encoding: create a new binary column for
    each category. For any one row, exactly one of the new
    columns is hot (1 or True) and the rest are 0 or False.
  - The lecture's flow on Titanic: one line, pd.get_dummies on
    the DataFrame with columns=['embarked'] and prefix
    'embarked'. Three new columns appear, named prefix plus
    underscore plus the original value: embarked_C, embarked_Q,
    embarked_S. Row 0 had embarked S, so embarked_S is True and
    the other two are False. A row with embarked C has only
    embarked_C True. The row with ID 5 had embarked Q, so only
    embarked_Q is True.
  - KEY TERM: dummy variable: a 0/1 column standing in for one
    category. get_dummies is named for it. (added definition)
  - For example, a region column with west, east, south, east,
    west, south:

      df_sh["region"] = ["west", "east", "south",
                         "east", "west", "south"]
      df_ohe = pd.get_dummies(df_sh[["region"]], columns=["region"],
                              prefix="region")
      print(df_ohe)

    Output:

         region_east  region_south  region_west
      0        False         False         True
      1         True         False        False
      2        False          True        False
      3         True         False        False
      4        False         False         True
      5        False          True        False

    Columns come out in alphabetical order of the category
    values. Each row has exactly one True. The values are the
    bool dtype in pandas 2.0 and later, which the lecture's output
    also shows as True and False.
  - Cost of one-hot (added): k categories become k columns. Fine
    for three ports. A zip code column with 40,000 distinct
    values becomes 40,000 mostly-zero columns, which is the
    sparsity problem from the preprocessing intro.

7. MANUAL ONE-HOT ENCODING
  - The lecture does this by hand too, not because it is better,
    but to show the mechanism step by step. The data is a gender
    DataFrame with four rows and two values, Male and Female.
  - The mechanism: a new column gender_male holds the answer to
    "is gender equal to Male?" converted to 1 for true and 0 for
    false. A second column gender_female does the same for
    Female. After that, rows 0 and 3 (Male) have gender_male 1
    and gender_female 0. Rows 1 and 2 (Female) have the reverse.
  - The Python idiom is a comparison followed by astype(int):
    (df['gender'] == 'Male') produces a True/False Series and
    astype(int) turns it into 1/0.
  - For example, the region column again:

      for r in ["east", "south", "west"]:
          df_sh["region_" + r] = (df_sh["region"] == r).astype(int)
      cols = ["region", "region_east", "region_south",
              "region_west"]
      print(df_sh[cols])

    Output:

        region  region_east  region_south  region_west
      0   west            0             0            1
      1   east            1             0            0
      2  south            0             1            0
      3   east            1             0            0
      4   west            0             0            1
      5  south            0             1            0

    Same picture as get_dummies, with ints instead of bools and
    one comparison per category instead of one function call.

8. WHICH ONE WHEN
  - Label encoding: quick integer codes, alphabetical, order is
    a side effect. The lecture uses it on sex, a two-valued
    column where 0 and 1 are all you need.
  - Ordinal encoding (OrdinalEncoder or a dictionary with map):
    the categories rank, and you say how. Class of service,
    education level, shirt size.
  - One-hot encoding (get_dummies or a boolean comparison per
    category): the categories do not rank, and the model must
    not be allowed to invent a ranking. Port of embarkation,
    color, region.
  - The notebook 4.2 heading files the dictionary-map approach
    under "Label Encoding (for ordinal data)" and get_dummies
    under "One-Hot Encoding (for nominal data)". Those parentheses
    are the decision rule: ordinal data gets integer codes in a
    chosen order, nominal data gets one-hot.
  - KEY TERM: nominal data: categories with no inherent order.
    KEY TERM: ordinal data: categories with an inherent order.
    (Both defined in the preprocessing intro lecture.)

9. KEY TAKEAWAYS
  - Algorithms want numbers. Strings must be encoded.
  - Label encoding: LabelEncoder, integers in alphabetical order.
  - Ordinal encoding: OrdinalEncoder with categories in your
    order, or a dictionary plus map(). Bigger number, higher
    rank.
  - One-hot encoding: get_dummies or a boolean comparison per
    category. One new column per category, one hot per row.
  - No order in the data means no order in the encoding. That is
    what one-hot protects.
