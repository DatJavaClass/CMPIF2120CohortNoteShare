================================================================
1. WHY ENCODE AT ALL
================================================================
  - Most machine learning algorithms operate only on numerical
    values. Real data is full of strings. Every string column
    has to be mapped to numbers somehow.
  - KEY TERM: categorical data: a column whose values are names
    or labels from a fixed set of categories (sex, port, class)
    rather than measured quantities (added definition).
  - KEY TERM: numerical data: a column whose values are numbers
    that support arithmetic (income, age) (added definition).
  - KEY TERM: feature encoding: transforming a categorical
    column into one or more numeric columns a model can use.
    The lecture also calls this "data transformations for
    categorical data".
  - KEY TERM: level / category: one distinct value a categorical
    column can take. Lecture example: high, medium, low are
    three levels, mapped to 2, 1, 0 respectively.
  - Many mappings are possible. The lecture covers three: label
    encoding, ordinal encoding, one-hot encoding.

================================================================
2. THE THREE ENCODINGS AT A GLANCE
================================================================
  - KEY TERM: label encoding: each category gets one integer,
    assigned in alphabetical order of the values. You do not
    choose the order.
  - KEY TERM: ordinal encoding: each category gets one integer
    in an order YOU specify, because the data has an inherent
    order (Third < Second < First).
  - KEY TERM: one-hot encoding: one new binary column per
    category. In any row exactly one of those columns is "hot"
    (1 or True) and the rest are 0 or False. For data with no
    inherent order, where imposing one would be wrong.
  - KEY TERM: nominal: categories with no natural order (port,
    gender) (added definition).
  - KEY TERM: ordinal: categories with a natural rank (degree
    level, ticket class) (added definition).
  - Lecture's decision rule: order irrelevant, label encode.
    Order matters and you can state it, ordinal encode. No
    order exists and none may be assumed, one-hot encode.
    Adopting a false order "by accident or on purpose" risks
    wrong modeling results.

4. LABEL ENCODING (sex)
================================================================
  - Code:
      le = LabelEncoder()
      df['sex_le'] = le.fit_transform(df['sex'])
      df[['sex', 'sex_le']].drop_duplicates()
  - KEY TERM: fit_transform: learn the mapping from the column
    (fit), then apply it (transform), in one call (added
    definition).
  - KEY TERM: drop_duplicates: keeps only rows whose combination
    of values across the selected columns is unique. A proper
    mapping yields exactly one row per category. Here, two.
  - Output (verified by running the notebook):
      sex     sex_le
      male    1
      female  0
    Mapping: female 0, male 1. Alphabetical, which is why
    female lands on 0. LabelEncoder sorts the unique values and
    numbers them from 0 (added).

================================================================
5. ORDINAL ENCODING (class)
================================================================
  - Alphabetical will not cut it when the data has an inherent
    order. Specify the order yourself.
  - Code:
      ordinal_order = [['Third', 'Second', 'First']]
      oe = OrdinalEncoder(categories=ordinal_order)
      df['class_ordinal'] = oe.fit_transform(df[['class']])
      df[['class', 'class_ordinal']].drop_duplicates()
  - Bracket rule (added): LabelEncoder takes a 1-D Series,
    df['sex']. OrdinalEncoder takes a 2-D DataFrame,
    df[['class']], and one category list per column, hence
    the nested list in ordinal_order.
  - Output (verified): Third 0.0, Second 1.0, First 2.0. Higher
    number for higher class of service. Three rows, one per
    class. OrdinalEncoder returns floats, so 0.0 not 0 (added,
    from run).
  - Any order you specify works. The choice is yours, not the
    encoder's.

6. MANUAL ORDINAL ENCODING (education, NOTEBOOK 4.2)
================================================================
  - Same result as section 5, done step by step with a
    dictionary and map instead of one scikit-learn call.
  - Data: five rows, four distinct degrees.
      df = pd.DataFrame({
          'education': ['High School', 'Bachelors', 'Masters',
                        'PhD', 'Bachelors']
      })
  - Code:
      education_map = {
          'High School': 0,
          'Bachelors': 1,
          'Masters': 2,
          'PhD': 3
      }
      df['education_encoded'] = df['education'].map(education_map)
  - Dictionary keys are the degree names, values are 0 through
    3. Series.map swaps each key for its value.
  - Output (verified): rows 0 through 4 read 0, 1, 2, 3, 1. Both
    Bachelors rows (index 1 and 4) become 1.
  - Transcript calls the dictionary "educational map". Notebook
    name is education_map. Notebook 4.2 also holds an identical
    dictionary named education_order (section 9).

7. ONE-HOT ENCODING (embarked)
================================================================
  - KEY TERM: dummy variable: a 0/1 (or False/True) column that
    flags whether a row belongs to one category. One-hot
    encoding is a set of dummy variables, one per category
    (added definition).
  - KEY TERM: cardinality: the number of distinct categories in
    a column. One-hot encoding creates that many new columns
    (added definition).
  - Code:
      df_ohe = pd.get_dummies(df, columns=['embarked'],
                              prefix='embarked')
      df_ohe[['embarked_C', 'embarked_Q',
              'embarked_S']].drop_duplicates()
  - New column names are prefix, underscore, original value:
    embarked_C, embarked_Q, embarked_S. The original embarked
    column is dropped from df_ohe (added, from run).
  - Output (verified, bool columns):
      index  embarked_C  embarked_Q  embarked_S  (original)
      0      False       False       True        S
      1      True        False       False       C
      5      False       True        False       Q
    Exactly one column is True per row.
  - Transcript says "embarked 401 in the original was c". Read
    as "embarked for row 1". Row 5 is the last row shown.
  - Notebook discrepancy: the cell's last line is
    df[['embarked']].drop_duplicates(), so Jupyter displays the
    original S, C, Q column, not the three dummy columns the
    lecture narrates. The dummy view is the line above it,
    computed but not displayed. A commented-out df_ohe.head()
    sits above that.

8. MANUAL ONE-HOT ENCODING (gender, NOTEBOOK 4.2)
================================================================
  - Not better, just transparent. Shown to expose the
    mechanism, "less of a black box".
  - Data: four rows, one column, two values.
      df = pd.DataFrame({
          'gender': ['Male', 'Female', 'Female', 'Male']
      })
  - Code:
      df['gender_male'] = (df['gender'] == 'Male').astype(int)
      df['gender_female'] = (df['gender'] == 'Female').astype(int)
  - Mechanism: the comparison yields True/False per row, and
    astype(int) turns True into 1 and False into 0.
  - Output (verified): rows 0 and 3 are gender_male 1,
    gender_female 0. Rows 1 and 2 are gender_male 0,
    gender_female 1.
  - Transcript says "four o's" and "one-hole decoding". Read as
    four rows and one-hot encoding.

================================================================
10. KEY TAKEAWAYS
================================================================
  - Models want numbers. Strings must be encoded.
  - Label encoding: LabelEncoder, alphabetical integers, you do
    not choose the order.
  - Ordinal encoding: OrdinalEncoder(categories=[[...]]) or a
    dictionary plus Series.map, you choose the order.
  - One-hot encoding: pd.get_dummies(df, columns=[...],
    prefix=...), one binary column per category, exactly one
    True per row, for data with no inherent order.
  - Manual versions: a dict with map for ordinal,
    (df['col'] == 'value').astype(int) for one-hot.
  - Check any encoding with df[[orig, new]].drop_duplicates().
    Row count should equal the number of categories.
